Cloud basics for the AskTravel beta

The ten ideas you need before you deploy, explained in plain words. Each one has an everyday comparison and what it means for AskTravel. At the end, a 10-question quiz checks what stuck.

About 8 minutesNo AWS knowledge neededCompanion to the deployment plan

The picture in one diagram

Today everything runs on your laptop. For the beta, the same containers run on a computer you rent from Amazon. Three kinds of things talk to it: your users, GitHub (to deliver new code), and a few outside services.

Public: reachable from the internetPrivate: inside the serverDelivery of new codeOutside services

Only Caddy faces the internet. Everything else is reachable only from inside the server, or by you through AWS's own management channel (SSM).

The ten ideas

1 · Server

A cloud server is a computer you rent by the hour

"The cloud" is somebody else's computer that never sleeps. You choose its size (memory and CPU) and the region, which is the city where the building is.

LikeRenting a flat instead of buying a house. You pay monthly, and the landlord fixes the plumbing.

In AskTravel: one EC2 server, type t4g.small (2 GB, Amazon's own arm64 chips), in us-east-1 (Virginia), ~$12 a month. It lives in a VPC, your own private network inside AWS. An Elastic IP keeps its address the same across restarts ($3.65 a month: every public IPv4 address costs money).

2 · DNS

DNS turns a name into an address

Computers find each other by numbers (IP addresses like 3.91.20.7). People prefer names. A domain is the name you buy; a DNS record says which number it points to.

LikeThe contacts app on your phone: you tap "Mum", it dials the number.

In AskTravel: an A record sends asktravel.<your domain> to the server's static IP.

3 · Ports and security group

A security group decides which doors are open

A server has numbered doors called ports: 443 for HTTPS, 80 for plain HTTP, 22 for SSH (remote login), 5432 for Postgres. A firewall lists which ones the internet may knock on; on EC2 it's called a security group. Every open door is something an attacker can try.

LikeA building with many doors where only the front entrance is unlocked, and it has a guard.

In AskTravel: the security group opens only 80 and 443. Port 22 isn't open at all; you reach the server through SSM (idea 8). Postgres and the agent API have no public port.

4 · HTTPS

HTTPS seals the envelope and proves who you are

HTTPS encrypts traffic so nobody on the café Wi-Fi can read chats or passwords. It needs a TLS certificate: a signed card that proves the server really owns the domain. Let's Encrypt gives these out free; they last 90 days.

A reverse proxy is the program at the front door. It handles HTTPS, then passes each request to the right app inside.

LikeA receptionist who checks the visitor in, then walks them to the right office.

In AskTravel: Caddy is the reverse proxy. It gets and renews the certificate by itself and forwards to Open WebUI.

5 · Containers

An image is the packed box; a container is the box opened and running

  • Image: your app plus everything it needs (Python, libraries, files), frozen into one file. Built once, runs the same anywhere.
  • Container: a running copy of an image. Stop it, start a new one from the same image, and you get the same app.
  • Registry: a warehouse for images. Tag: the label on the box.
  • Docker Compose: one file that lists the containers and how they connect.
LikeA frozen ready meal (image) and the hot meal on your plate (container). The freezer aisle is the registry.

In AskTravel: images live in ECR (AWS's private registry), tagged with the git commit they were built from, so you always know exactly which code is running. docker-compose.prod.yml runs Caddy, Open WebUI, the API and Postgres.

6 · CI

CI checks every change before it is merged

Continuous integration: each time you open a pull request, a robot runs the tests and the linter. A red result blocks the merge. It catches mistakes while they're still cheap.

LikeSpell-check that runs before you can hit "send".

In AskTravel: a GitHub Actions workflow (a YAML file in .github/workflows/) runs pytest and ruff on a runner, a short-lived computer GitHub lends you.

7 · CD

CD ships each merged change to the server

Continuous deployment: after a merge, the robot builds the image, pushes it to the registry and puts it on the server. An environment with a required approval makes it wait for your click first.

After the switch, a health check asks the app "are you OK?" (/agent-health). If the answer is no, a rollback puts the previous image back.

LikeA conveyor belt with one human checkpoint, and a reverse gear if the new part doesn't fit.

In AskTravel: merge → test → build → you approve → deploy.sh <commit> → health check → automatic rollback on failure. No terminal needed.

8 · Private access

No back door at all: the server checks in with AWS

To deploy or fix things you need to run commands on the server. The classic way is SSH on port 22, which invites a constant stream of password-guessing bots. AWS's SSM agent turns it around: it runs on the server and connects out to AWS, asking "anything for me?". Session Manager gives you a shell that way, and Run Command runs a script.

LikeA house with no letterbox that collects its own post from the post office. Nobody can knock, but messages still arrive.

In AskTravel: you open a shell with aws ssm start-session, and the deploy job uses Run Command. There's no SSH key anywhere.

9 · Secrets and least privilege

Badges that expire, each opening as few doors as possible

IAM is AWS's system of identities and permissions. An IAM role is an identity with no password or key: whoever is allowed to use it gets credentials that expire within hours. Least privilege means each role can do only its one job, so a mistake or a leak does little harm. Secrets (API keys, passwords) never go in git; here they live in Parameter Store, encrypted.

LikeA visitor badge that opens two rooms and stops working tonight, instead of a copied master key.

In AskTravel: the server has a role that can add backups to one S3 bucket, pull one image and read its secrets, nothing more. GitHub gets a role through OIDC (a trusted sign-in from GitHub), so no AWS keys are stored anywhere. The root account gets two-factor login and is put away.

10 · Backups and monitoring

Assume things break, and find out before your users do

  • Backup: each night, pg_dump copies the database to S3, Amazon's file storage, and AWS takes a snapshot of the whole disk. You can lose at most one day of data.
  • Restore drill: restore a backup once, for real. A backup you've never restored is a hope, not a backup.
  • Uptime check: an outside service visits the site every few minutes and emails you if it's down.
  • Heartbeat: the backup job checks in after each run; silence means it failed.
  • Alarms: CloudWatch watches the server's memory, disk and health and emails you; AWS Budgets emails you if the bill passes a limit you set.
  • Tracing: LangSmith shows what the agent did in each chat.
LikeSmoke alarms and a fire drill. The alarm tells you something's wrong; the drill proves the exit works.

In AskTravel: S3 backups, daily EBS snapshots, CloudWatch alarms, UptimeRobot, Healthchecks.io, AWS Budgets and LangSmith. About $1–2 a month in total.

One change, start to finish

Here is how a prompt fix reaches your beta users once everything is set up:

  1. You change the prompt on a branch and open a pull request. CI runs the tests: green.
  2. You merge. CD starts: GitHub builds a new image, tags it with the commit, and pushes it to ECR.
  3. GitHub asks for your approval. You click "Approve".
  4. The job signs in to AWS with OIDC and asks SSM Run Command to run deploy.sh. The server pulls the image and swaps the API container.
  5. The health check passes and the run goes green. If it had failed, the rollback would have restored the previous image.
  6. Users open asktravel.<your domain>. DNS finds the server, Caddy handles HTTPS, and they chat with the new prompt.
